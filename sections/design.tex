\section{Hypotheses}\label{sec:hypotheses}
Chapters \ref{cha:problemanalysis} and \ref{cha: technicalanalysis} have outlined weaknesses and shortcomings in the \acs{ReID} domain, as well as the potential for improvement when combined with \acs{SR}. Based on these insights, two hypotheses have been formulated to guide the subsequent analysis along.
\\\\
The intuitive way to improve performance is to use data augmentation to introduce variations that can reflect the challenges the model should learn to handle. This leads to the first hypothesis:

\begin{itemize}
    \item \hypertarget{hypothesis:1}{\textit{Hypothesis 1}}: Training the \acs{ReID} module on augmented images will improve performance when evaluated under \acf{InD} and \acf{OOD} conditions.*
\end{itemize}
\noindent * The conditions for \acs{InD} and \acs{OOD} is defined in section \ref{Reidteststrategy}
\\\\
Alternatively, \acs{SR} is integrated to improve image quality and enhance features for the \acs{ReID} model. This leads to the second hypothesis:

\begin{itemize}
    \item \hypertarget{hypothesis:2}{\textit{Hypothesis 2}}: Feeding data through the \acs{SR} module, before it enters the \acs{ReID} module, will lead to a better performance. 
\end{itemize}

\noindent As the project objective is to investigate how \acs{SR} can enhance the performance of \acs{ReID}, each architecture presented in this chapter was selected with the intent of establishing a fair and consistent foundation for comparison, rather than to achieve State-of-the-Art results. Furthermore, both of the chosen model architectures have low parameter counts, for the purpose of solving the problem by improving model and training setup, instead of purely relying on adding more parameters. The experimental setups are built around the hypotheses and will be explained at the end of the chapter.

\section{ReID Module} \label{sec: Designreidmodule}
This section introduces the chosen \acs{ReID}-architecture, which is described based on the original \acs{OSNet} publication \cite{OSNet}, along with the training and test strategies, loss function, and evaluation metrics. 

\subsection{OSNet} \label{sec:methodreid}
The \acf{OSNet} architecture introduced in Section \ref{sec:omniscale}, demonstrates strong performance across several person re-identification benchmarks \cite{OSNet}. In Section \ref{outofdistributiontest}, it was concluded that \acs{OSNet} performance still has room to improve, when confronted with lower resolution scales or more aggressive compression. However, given its omni-scale design and lightweight architecture, \acs{OSNet} is a well-suited backbone for exploring improvements under resolution-degraded conditions, particularly in combination with super-resolution techniques. 
\\\\
As mentioned in Section \ref{sec:omniscale}, the model adaptively captures discriminative features for person \acs{ReID} across different spatial scales. This is achieved through \acf{OSBlock}s, which are the fundamental building units of \acs{OSNet}. The details for the architecture are presented in this section, based on Figure \ref{fig:osnetpipeline}.

\begin{figure} [H]
    \centering
    \includegraphics[width=1\linewidth]{osnetpipelinebud.png}
    \caption{An overview of the pipeline for the OSNet module.}
    \label{fig:osnetpipeline}
\end{figure}

\noindent The first \acs{OSBlock} receives a feature map created by an initial standard convolution and max pooling, with the following \acs{OSBlock}s using the feature map from the previous layer. This process is repeated until the fourth convolution stage, which is then followed by a pointwise \textit{1x1} convolution, to fuse information across all channels together. Global average pooling is used to collapse the spatial dimensions into one value per channel, resulting in a feature vector that is passed through a fully connected layer to produce the final embedding used for person \acs{ReID}. 
\\\\
The internal process of a single \acs{OSBlock} is presented in Figure \ref{fig:osblockpipeline}. 

\begin{figure} [H]
    \centering
    \includegraphics[width=1\linewidth]{osblockpipeline.png}
    \caption{An overview of the process inside the \acs{OSBlock}s.}
    \label{fig:osblockpipeline}
\end{figure}

\noindent In these blocks, the feature map is processed by a pointwise \textit{1x1} convolution, which reduces the channel dimensions. Subsequently, four parallel streams apply depthwise convolutions with kernel sizes \textit{3x3}, \textit{5x5}, \textit{7x7}, and \textit{9x9}, corresponding to increasing receptive fields that capture features at different scales, which defines the omni-scale capability. Each branch uses these depthwise separable convolutions, also called lite \textit{3x3}, to improve efficiency. The outputs from the four parallel streams are  aggregated with channel-wise adaptive aggregation. The aggregation is implemented through a lightweight gating mechanism performed by an internal mini neural network that learns to weight feature channels based on the extracted feature maps.  The purpose of the aggregation gate is to dynamically combine scale-specific features into a unified representation that is robust to variations in spatial scale. 
\\\\
This fusion is what enables the models omni-scale behavior. After the fusion, a pointwise \textit{1x1} convolution restores the original channels. The final result is added to the input of the block by a skip connection and passed through a ReLU activation function. Each stage contains two \acs{OSBlock}s with \texttt{stride=1}, before an \acs{OSBlock} with \texttt{stride=2} down-samples the feature map.

\subsection{Loss Function}\label{sec:reidloss}
The choice of a loss function is fundamental to the optimization process, and the overall shaping of representations learned by the model \cite{lossfunction}. In person \acs{ReID}, the loss function must encourage the learning of discriminative features that can separate identities while remaining efficient during training. In addition, because \acs{ReID} is an open-set problem, it requires the model to generalize effectively to identities not seen during training. This section introduces the loss function used for \acs{OSNet} and explains how it supports effective feature learning for identity classification.

\subsubsection*{Multiclass Cross-Entropy Loss}
Multiclass cross-entropy loss, also known as softmax loss, is commonly used for classification tasks where each input has one correct class \cite{softmax}. It works by applying a softmax function to the model's output logits to produce a probability distribution for each class, and then calculating the negative log-likelihood of the true class. Formula \ref{formula:softmaxloss} shows the softmax loss written directly in terms of logits, as presented in \cite{softmax}:

\begin{equation}
\mathcal{L}_i = - f_{y_i} + \log \sum_{j} e^{f_j}
\label{formula:softmaxloss}
\end{equation}

\begin{description}
    \item[$\mathcal{L}_i$]: Softmax loss for the $i$-th sample.
    \item[$f_{y_i}$]: Logit corresponding to the true class.
    \item[$y_i$]: Ground-truth class index for sample $i$.
    \item[$f_j$]: Logit for class $j$.
    \item[$\sum_j e^{f_j}$]: Normalization term over all classes.
\end{description}

\noindent This encourages the model to assign a high probability score to the correct class, while penalizing confident but incorrect predictions. The output probabilities can be interpreted as the model's confidence in each class. However, these probabilities are influenced by the scale of the model's logits, which is affected by the regularization strength used in training. Stronger regularization punishes large parameter values, which can reduce the scale of the logits and result in softer softmax outputs. In contrast, lower regularization may allow for larger softmax outputs. Label smoothing is a regularization technique commonly used in combination with softmax loss, as it prevents the model from becoming overconfident in its predictions, by softening the target labels instead of using one-hot encoded labels \cite{labelsmoothing}. This is particularly beneficial for person \acs{ReID}, as it addresses the challenge of limited training samples per identity. By preventing extreme confidence on training identities, label smoothing encourages the model to learn more robust features that generalize better to unseen test identities, a critical requirement for the open-set nature of person \acs{ReID}.

\subsection{Evaluation Metrics}\label{reidmethodevalmetric}
The evaluation metrics help measure how well the models perform on a given task \cite{evaluationmetrics}. Therefore, selecting the appropriate metrics is essential to ensure that the evaluation reflects the objective of the task. In the context of person \acs{ReID}, the evaluation must capture the model's ability to correctly identify individuals, as well as the quality of the ranking of retrieved matches. This section introduces the evaluation metrics used for the person \acs{ReID} module.

\subsubsection*{Rank}
Rank-\textit{k} metrics are widely used in \acs{ReID} to measure how good the system is at getting a correct identity match within a certain range. Rank is based on a concept called the Cumulative Matching Characteristic, which describes the probability that the first correct match appears within the top \textit{k} results of all queries evaluated. For example, a Rank metric with \texttt{k = 1} would answer the question "For how many queries were the top match the correct identity?" while a Rank with \texttt{k = 5} would answer "For how many queries did the correct identity appear in the top 5 matches?". This is the same process with different valued rank \textit{k} metrics, the only difference is how much of a query will be accounted for.
\\\\
Because it is a Cumulative Metric, it will count a query as a success if the correct match is within the top \textit{k} positions. In other words, once a query has its first correct match at rank \textit{r}, it is counted as a success for all Rank-\textit{k} metrics where \(r \le k\). This is done on multiple queries where an average is then taken of the successes for each Rank-\textit{k} \cite{rankmetricEvidently}. A more in-depth explanation can be seen in the Rank-\textit{k} Formula \ref{formula:Rank}.

\begin{equation}
\mathrm{Rank}\text{-}k
\;=\;
\frac{1}{Q}\sum_{q=1}^{Q}\mathbf{1}\!\left[r_q \le k\right]
    \label{formula:Rank}
\end{equation}

\begin{description}
    \item[$r_q$]: The location of the first correct match for the query $q$.
    \item[$\mathbf{1}\lbrack r_q \le k\rbrack$]: Turns each query into a binary success criterion. If $r_q \le k$, return 1; otherwise 0.
\end{description}

\noindent In this project, specifically Rank-1, Rank-5, Rank-10, and Rank-20 have been calculated. However, Rank-1 is the primary focus, as it directly measures whether the correct identity is retrieved as the top-ranked result.


\subsubsection*{\acs{mAP}}
\acf{mAP} is a commonly used metric to examine the performance of both object detection and information retrieval systems, such as \acs{ReID}. \acs{mAP} can differ, depending on what it is being used for, but in a \acs{ReID} context, it works by measuring how good the system is at retrieving the correct identities across the entire ranked gallery list, which also makes it ideal to work alongside the Rank-\textit{k} metric, as it estimates all true matches, and not just a given \textit{k} range. As the name implies, \acs{mAP} is found by calculating the mean of the overall Average Precisions of all valid queries. In \acs{ReID}, Average Precision is computed from the ranked gallery list, by measuring precision at every correct match starting from the highest similarity score to the lowest. An average of these precisions is then taken to get the Average Precision of that query as seen in Formula \ref{formula:AP}. 

\begin{equation}
\mathrm{AP}(q)
\;=\;
\frac{1}{R_q}\sum_{i=1}^{N} P_q(i)\,\mathrm{rel}_q(i)
\label{formula:AP}
\end{equation}

\begin{description}
    \item[$P_q(i)$]: The precision that is calculated for correct/relevant match $\mathrm{rel}_q(i)$ at rank $i$ for query $q$.
    \item[$\mathrm{rel}_q(i)$]: "Relevance" at rank $i$ for query $q$.
    \item[$R_q$]: Total number of relevant matches in the gallery for query $q$.

\end{description}

\noindent Meanwhile, \acs{mAP} is the mean of those Average Precisions across all the valid queries as seen in Formula \ref{formula:mAP}. 

\begin{equation}
\mathrm{mAP}
\;=\;
\frac{1}{Q}\sum_{q=1}^{Q}\mathrm{AP}(q)
\label{formula:mAP}
\end{equation}
\begin{description}
    \item[$\mathrm{AP}(q)$]: The Average Precision as seen in formula \ref{formula:AP} for query $q$.
\end{description}

\noindent This means it both accounts for how good the system is at finding matches, but also how good it ranks them \cite{mAPlightly}. Because \acs{mAP} evaluates the model’s ability to retrieve all relevant matches, it is selected as the primary metric for model selection.

\subsection{Training Strategy}\label{trainingstragegyreid}
The \acs{ReID} module will be trained on a combination of Market-1501 \cite{CVATM1501}, \acs{MSMT17} \cite{wei2018person} and \acs{CUHK03} \cite{KaggleCUHK03}, providing 2,355 unique identities across diverse surveillance conditions. This multi-dataset training approach is chosen to ensure that the model learns generalizable features rather than dataset-specific patterns. Each dataset contributes with distinct characteristics: Market-1501 provides realistic detector noise in the form of distractors, \acs{CUHK03} emphasizes controlled cross-camera matching scenarios, and \acs{MSMT17} contributes with 15 cameras across indoor and outdoor scenes, captured at different times of day.

\subsection{Combined Dataset}\label{combineddataset}
Constructing a person \acs{ReID} dataset requires careful handling of identity labels, particularly when combining multiple datasets. The primary challenges are avoiding overlapping person identities and ensuring consistent person-ID indexing across datasets.
\\\\
To prevent person-ID conflicts and to guarantee continuous ID values, a \texttt{JSON} mapping file is created during dataset construction. Each original person-ID is first augmented with a dataset-specific prefix and then mapped to a new, continuous global identity index, e.g. \texttt{"10023": 56}. This procedure ensures that all identities remain unique across datasets while preserving a single, consistent person-ID per individual. The resulting continuous ID values are directly compatible with cross-entropy-based classification losses.
\\\\
During the creation of the mapping file, every tenth newly assigned person-ID is reserved for the validation set. This results in 238 validation identities, while the remaining 2,117 identities are used for training. Selecting identities, rather than individual images, for validation ensures that the model is evaluated on previously unseen persons, which aligns with the open-set nature of person \acs{ReID}. The decision to include every tenth identity further guarantees that the validation set contains a sufficiently large and diverse collection of images for reliable evaluation.
\\\\
For training, each data sample consists of an image and its corresponding person-ID. Camera-ID information is not required during training, but it is used during validation and testing to support standard \acs{ReID} evaluation protocols.
\\\\
The three datasets: Market-1501, \acs{MSMT17}, and \acs{CUHK03}, differ in directory structure and filename conventions. Therefore, each dataset is first loaded separately using a dataset-specific parsing routine. These routines iterate over all image files within the dataset directories and extract the person-ID and camera-ID by matching predefined filename patterns. Each image sample is ultimately represented by three attributes: the image path, the person-ID, and the camera-ID.
\\\\
A common evaluation protocol for person \acs{ReID} follows a query–gallery retrieval setup. This is already implemented in the existing test sets, but needs to be implemented for the validation identities. For validation, one image per validation identity is randomly selected and placed in the query set. The remaining images are assigned to the gallery set, excluding samples that share both the same person-ID and camera-ID as the query image. This setup follows standard person \acs{ReID} evaluation practice and ensures a fair and realistic retrieval scenario.
\\\\
Once processed individually, the three training datasets are merged into a single unified dataset using \texttt{ConcatDataset} from \texttt{torch.utils.data}. This enables seamless training across all datasets while preserving consistent person-ID and camera-ID labeling. The same merging strategy is applied to the query and gallery sets during validation, whereas the test sets are kept separate to allow dataset-specific evaluation.

\section{SR Module}\label{sec:designSRmodule}
This section presents the chosen \acs{SR} architecture, as well as the training strategy using the two \acs{SR} datasets presented in Section \ref{sec: superresdata}. Based on the technical analysis of the perception-distortion trade-off in the \acs{SR} domain, presented in \ref{subsec:perception-distortion-tradeoff}, a low distortion model is considered more suitable for integration with \acs{ReID}, as it reduces the risk of introducing \acs{SR} artifacts.

\subsection{EDSR}
\acf{EDSR} is a \acf{ResNet} based architecture for single image \acs{SR}, designed with an emphasis on high reconstruction quality and stable training. As mentioned in Section \ref{sec: edsr relatedworks}, \acs{EDSR} showed strong performance when optimizing for low distortion, making it a promising candidate as a pre-processing unit for the task of \acs{ReID}. For this project, the base configuration of \acs{EDSR} is selected due to its balance between reconstruction quality and computational efficiency. Table \ref{tab:edsr-config} summarizes the base \acs{EDSR} configurations, consisting of 16 residual blocks with 64 feature channels.

\noindent As shown in Figure \ref{fig:edsrpipeline}, the up-sampling stage is implemented by learnable up-sampling modules, placed at the end of the network, so that most of the computation is performed in the \acf{LR} space, effectively meaning only the final layers project the feature maps to \acf{HR}. The internal structure of the up-sampling module is illustrated in Figure \ref{fig:upsampleblockpipeline}, which shows the learnable nature of the up-sampling process. Specifically, the up-sampling module uses a sub-pixel convolution approach called \texttt{PixelShuffle}, where a convolutional layer first expands the feature maps by a factor of scale\textsuperscript{2}. This convolutional layer contains trainable weights, making the up-sampling process learnable rather than relying on fixed interpolation methods, such as bilinear or bicubic up-sampling. The \texttt{PixelShuffle} operation then rearranges these learned features into the spatially up-scaled output \cite{shi2016subpixel_arxiv}.

\subsection{Loss Function}\label{sec:srloss}
For the training of the \acs{SR} module, \acf{MAE}, also called \acf{L1}, was used as the training objective, following the original \acs{EDSR} implementation \cite{lim2017edsr}. \acs{L1} loss is less sensitive to outliers than \acs{L2} loss, as large errors are not squared and therefore receive less emphasis during optimization \cite{Goodfellow2016}.

\subsection{Evaluation Metric}
The primary metric for evaluating the \acs{SR} module is \acf{PSNR}, supported by \acf{SSIM}. Both measure distortion and fit the chosen low-distortion \acs{SR} strategy, which aims to avoid hallucinated details and artifacts that could hurt downstream \acs{ReID} performance \cite{Blau2018PerceptionDistortion}.

\subsubsection*{PSNR}
\acs{PSNR} measures the pixel-wise difference between the super-resolved output and the reference \acs{HR} image, derived from the mean squared error (MSE). A higher \acs{PSNR} means lower distortion and more accurate reconstruction. For \acs{ReID}, the goal is to keep real discriminative details and avoid adding fake ones. \acs{PSNR} is therefore the primary model-selection criterion, with the best model checkpoint being chosen by the highest validation \acs{PSNR}, to prioritize pixel accuracy over perceptual effects that could create false details \cite{lim2017edsr}.

\subsubsection*{SSIM}
\acs{SSIM} measures structural similarity (luminance, contrast, structure) between reference and output \cite{Wang2004SSIM}. Values close to 1 mean structures are well preserved. \acs{SSIM} is reported with \acs{PSNR}, to check that edges and textures critical for \acs{ReID} embeddings remain intact. Using both \acs{PSNR} and \acs{SSIM} reflects the low-distortion strategy and reduces the risk of hallucinations and artifacts that could harm \acs{ReID} discrimination \cite{Blau2018PerceptionDistortion}.

\subsection{Training and Validation Strategy}\label{SRtrainingdata}
To investigate which training approach produces the best \acs{SR} performance for real-world degradations, two training strategies are compared: training from scratch on domain-specific data (\acs{RELLISUR}) versus finetuning on synthetic data (\acs{DIV2K}). This comparison is motivated by the fundamentally different degradation characteristics of the two datasets. \acs{RELLISUR} consists of real low-light and low-resolution image pairs captured under natural imaging conditions, where degradations arise from the physical image capture process rather than synthetic down-sampling. In contrast, \acs{DIV2K} contains high-quality images with synthetically generated low-resolution counterparts created through bicubic downsampling.
\\\\
The first training approach trains \acs{EDSR} from scratch exclusively on \acs{RELLISUR}, exposing the model only to realistic degradation patterns. The hypothesis is that domain-specific training may produce better results when the test data contains similar real-world degradations. The second training approach takes the best checkpoint from the scratch model and finetunes it on \acs{DIV2K}. The hypothesis for this approach is that finetuning on high-quality synthetic data may improve reconstruction stability and generalization by refining the learned representations under controlled degradation settings.
\\\\
Both models are evaluated on the same \acs{RELLISUR} validation and test sets to enable direct comparison and determine which training strategy is most effective for handling realistic surveillance-like degradations.

\subsubsection{Patch-Based Training Strategy}
The \acs{RELLISUR} and \acs{DIV2K} datasets were prepared by cropping aligned \acs{LR} and \acs{HR} patches of size \textit{64×128} and \textit{128×256} pixels from the original images. This preprocessing was performed prior to training, creating a fixed dataset of patch pairs.
\\\\
The patch dimensions were chosen to match typical person bounding box sizes in \acs{ReID} datasets, such as Market-1501 (\textit{128×64}) and \acs{MSMT17} (\textit{256×128}), as described in Section \ref{sec:reid-dataset}. Training the \acs{SR} module on patches of similar dimensions ensures that the model learns to upscale images at scales relevant to the downstream \acs{ReID} task. This alignment between \acs{SR} training data and \acs{ReID} input data is critical for effective integration of the two modules \cite{lim2017edsr}.

\section{Model Setups} \label{sec:model_definitions}

In order to validate the hypotheses defined in Section \ref{sec:hypotheses}, three experiments will be conducted. For the purpose of these experiments, four models will be implemented in Chapter \ref{cha: implementation}. The \hyperlink{model:baseline}{first model} will serve as a baseline for comparison. The \hyperlink{model:augmented}{second model} will be used to validate \hyperlink{hypothesis:1}{\textit{Hypothesis 1}}. The \hyperlink{model:sequential}{third} and \hyperlink{model:endtoend}{fourth} models will be used to validate \hyperlink{hypothesis:2}{\textit{Hypothesis 2}} at two different integration levels. \subsection*{\hypertarget{model:baseline}{Baseline} Model}

\subsection*{\hypertarget{model:augmented}{Augmented} Model}
\hyperlink{model:augmented}{Augmented} model of \acs{OSNet} trained from scratch using the strong augmentation pipeline from Table \ref{tab:three_subtables}.

\subsection*{\hypertarget{model:sequential}{Sequential} Model}
Pretrained \hyperlink{model:baseline}{Baseline} model of \acs{OSNet} in sequential combination with pretrained \acs{EDSR}. \hyperlink{model:sequential}{sequential} is defined as the two modules (\acs{SR} and \acs{ReID}) being combined without further training.

\subsection*{\hypertarget{model:endtoend}{End-to-end} Model}
Pretrained \hyperlink{model:baseline}{Baseline} model of \acs{OSNet} trained end-to-end with pretrained \acs{EDSR}, using the strong augmentation pipeline from Table \ref{tab:three_subtables}. \hyperlink{model:endtoend}{End-to-end} is defined as the modules being combined, such that losses from the \acs{ReID} module back-propagate into the \acs{SR} module.
